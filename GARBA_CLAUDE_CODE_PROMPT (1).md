## 3. Что уже работает (не сломать)

- создание комнаты по коду, вход игроков, автообновление лобби (polling ~1 раз/сек);
- старт игры только при полной комнате;
- определение раздающего — открываются карты по кругу до первого Туза;
- открытие козыря и раздача по 5 карт каждому из 4 игроков;
- игрок видит только свои карты, чужие руки backend наружу не отдаёт;
- этап торгов **РАЗ / ПАС** для 4 игроков, ход передаётся через backend.

Текущие endpoints (менять контракт без предупреждения нельзя):
```
GET  /health
POST /rooms                      { playerId, name, capacity }   capacity 4..7
GET  /rooms/:id?playerId=...
POST /rooms/:id/join             { playerId, name }
POST /rooms/:id/start            { playerId }   только создатель
POST /rooms/:id/dealer/continue  { playerId }   только создатель
POST /rooms/:id/bid              { playerId, bid }
```

## 4. Железные правила проекта

1. **Backend — единственный источник истины.** Flutter только отображает состояние и
   отправляет действия. Flutter НИКОГДА сам не решает: чей ход, какая карта допустима,
   кто раздающий, какой козырь, кто выиграл торги, кто взял взятку.
2. **Правила для 4 игроков — подтверждённые, менять нельзя:**
   - колода 21 карта: черви 6,7,8,9,10,J,Q,K,A (9 карт) + J,Q,K,A в ♠ ♦ ♣ (12 карт);
   - 1 карта открывается как козырь, оставшиеся 20 раздаются по 5 каждому;
   - в торгах для 4 игроков доступны только **РАЗ** и **ПАС**;
   - кнопки **ДВА** для 4 игроков нет, и backend обязан отклонять `ДВА` даже при ручном
     запросе через curl.
3. **Ничего не выдумывать.** Если правило игры тебе неизвестно — останавливайся и
   спрашивай меня. Придуманные правила хуже, чем отсутствие кода.
4. Работать маленькими шагами: одно изменение → сборка → проверка → следующий шаг.
5. Перед серьёзной заменой файла делать бэкап по принятой схеме
   (`index.ts` → `index_oldN.ts`, `main.dart` → `main_oldN.dart`).
6. Комментарии в коде и тексты в UI — на русском.

**Шаг 2. Задай мне вопросы по правилам игры.**
Это самое важное. Я — носитель правил, ты их не знаешь. Спрашивай по одному блоку за раз,
не вываливай 30 вопросов сразу. Как минимум нужно выяснить:

*Торги:*
- кто говорит первым — раздающий, игрок слева от него, или другой?
- что значит «РАЗ» по смыслу (заявка на количество взяток? на игру?);
- что происходит, если все сказали ПАС;
- может ли игрок сказать РАЗ после чужого РАЗ, есть ли перебивание;
- кто считается победителем торгов и что он получает;
- как используется открытый козырь: забирает ли его победитель торгов в руку, что тогда
  сбрасывает, или козырь просто лежит открытым как указатель масти.

*Розыгрыш:*
- кто делает первый ход;
- обязан ли игрок ходить в масть, если она есть на руках;
- обязан ли козырять, если масти нет;
- как определяется победитель взятки;
- старшинство карт внутри масти и роль козырной масти;
- кто ходит первым в следующей взятке.

*Очки и конец партии:*
- как считаются очки за взятки;
- что получает победитель торгов при выполнении и при невыполнении заявки;
- до скольки очков идёт партия / сколько раздач;
- кто раздаёт следующую раздачу.

*Другие составы:*
- как меняется колода и раздача для 5, 6, 7 игроков;
- в каких составах появляется «ДВА» и что оно означает.
